# Agent 协作规则

这套公开规则帮助多个 Agent 通过同一份私有资料接续工作、保存已确认事实，并维护既有持仓表。日常运行只需要本仓库的固定发布版本和已授权的私有资料连接，不依赖任何私有 GitHub 仓库。

公开仓库保存通用规则、校验脚本与虚拟测试；私人背景、偏好、账户、余额、文档标识和运行回执留在用户自己的私有资料库。

## 从这里开始

1. 按平台启动指令读取用户的私有资料索引，核对来源与权限；将其 `agent_runtime` 对象作为运行 manifest。
2. 按 [入口与版本](docs/入口与版本.md) 读取 manifest 指定的精确 release。不要以默认分支、搜索摘要或旧聊天代替该版本。
3. 从 manifest 的资源映射读取当前偏好、项目背景和近期记录；再按当前任务读取相关业务资料。
4. 确认新持仓、成交、现金余额或转账状态时，必须在本轮执行 [持仓同步](docs/持仓同步.md)，分别报告表格、确认链和近期记录的保存结果。

私有索引的位置由平台启动指令提供，不写入本仓库。启动配置只需该索引 ID，公共仓库及固定版本从 `agent_runtime.release` 取得。未配置时仅询问这一入口；已配置但读取失败时说明具体缺口，不让用户重复提供基础资料。

## 维护方式

本仓库是通用规则的唯一维护源。Drive 备用规则由同一次发布 bundle 生成，并校验与对应 release 一致；不得在云端手工维护另一套规则。私有 manifest 固定 release 的完整 commit，升级时由维护者核验兼容性后更新。迁移前配置只保留为历史缓存，不继续维护两套当前配置。

使用备用包时，先用独立于该包的可信哈希能力核对完整原始字节与私有 manifest 固定的哈希。通过前不得执行、导入或安装包内脚本来为它自身验证。

规则文件存在不等于平台已经加载，工具存在不等于调用成功，保存回执不等于后台同步或并发安全已经验收。平台接入需分别核验；不因读取失败而公开私人资料或扩大权限。
