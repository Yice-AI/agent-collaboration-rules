# 隐私与发布

公开的是通用方法，不是个人项目。去掉姓名不等于资料适合公开；账户组合、资金路径、余额、私人计划、来源定位和文档标识同样可能暴露个人背景。

## 公开与私有边界

| 可公开 | 只留私有资料库 |
|---|---|
| 不含个人实例的通用规范、schema、纯校验脚本 | 私有 manifest 及所有真实资源值 |
| 完全虚构、无真实来源关联的测试数据 | 账户、持仓、现金、成交、转账、私人偏好和项目背景 |
| 空白启动模板与待保存模板 | 原始截图、回单、聊天原文、运行日志和真实保存回执 |
| 不含真实标识的发布清单和测试摘要 | 私有仓库名、云盘 ID/URL、本人姓名、联系方式和本机真实路径 |

密码、PIN、私钥、助记词、验证码密钥、恢复码、卡安全码等凭据不进入本项目台账。正式事实和近期记录只保留完成任务必要的信息。

连接器可读取整文件不等于已实现字段隔离；文件私有也不代表全部第三方授权已审计。每次写入按规范核对目标权限，不擅自公开、共享或扩大授权来解决访问问题。

## 单一维护源

1. 只在公共规则源修改通用文档和校验逻辑。个人配置变更直接维护私有资源，禁止把真实值放进公开提交后再删除。
2. 发布前检查完整文件清单、暂存差异、Git 历史来源、测试输出和打包产物；使用允许清单与隐私扫描，人工核对意外个人背景。自动扫描不是无泄露保证。
3. 同一 release 生成公共分发文件和 Drive 备用 bundle。清单包含可核对的版本、文件列表和内容哈希；不得从私有旧仓库整库复制或带入其 Git 历史。
4. 由维护者先核对发布可读性、文件一致性、schema 兼容性与所需审查，再更新私有索引 `agent_runtime.release` 中固定的完整 commit、版本、bundle 哈希和备用文档引用。升级前实际读取索引完整原生正文、权限、父目录和同次 `revisionId`，保存原样私有备份；程序化仅修改本次获授权的 release 字段，保留 `resources`、其他索引字段和未授权的 release 字段。以该次读取的 `requiredRevisionId` 条件提交；禁止无条件覆盖或 `targetRevisionId` 合并。冲突时停止旧候选，重新完整读取并核对他人变更后再准备。成功后重读完整正文与权限，核对 release 精确值、未修改部分全等及同版备用包。旧配置只保留历史，不继续维护。升级不能静默改变基线、既有事件、允许字段或私人资源权限。
5. 发布完成、manifest 更新、平台启动指令安装以及真实业务执行分别读回。任何一步未通过，都明确实际完成范围。

Drive 备用不接受手工规则修订；发现错误回到公共源修复并发布新版本。公开规则可以正常被检索，但不得把私人正文、真实文档 ID 或业务数值放进公开搜索查询、issue、注释或报错材料。

本地候选、下载的私人数据和工具回执放在不会进入公共提交或 bundle 的私有工作目录。临时文件同样需要边界，不因其名称是“测试”“草稿”就允许公开。

## 发布产物校验

在规则仓库根目录使用明确的文件允许清单生成 bundle。以下路径是通用示例，版本号及预期哈希须来自本次实际发布，不得照抄旧值：

```sh
python3 -B scripts/build_bundle.py build --root . --allowlist bundle-paths.txt --version VERSION --out _private/release/bundle.json
python3 -B scripts/build_bundle.py verify --input _private/release/bundle.json --expected-sha256 EXPECTED_SHA256
```

`build` 输出的 `published:false` 表示只完成本地打包，不表示公共仓库或 Drive 已发布。bundle 不含时间、commit 或 `release.json`；其 SHA256 按单行 UTF-8 文件的原始字节计算，不带末尾 LF。manifest 中的 commit 与 bundle 哈希必须由维护者分别核对到同一次发布。

Drive 上传后的正文还须重新读取校验；原生文档的结构性末尾 LF 按 [入口与版本](入口与版本.md) 的限定方式处理。消费备用包时须先用独立可信工具核对外层原始字节哈希，外层通过前不能运行包内校验脚本来证明该包可信。公开文件与私有 manifest 的写入结果分别给出回执，不把生成 bundle 当成平台已加载新规则。
