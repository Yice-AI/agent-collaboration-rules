# 写入范围保护

持仓表写入必须经过同版 `scripts/holdings_guard.py`。调用方仍负责用户授权、账户识别、事实来源、权限和日期；脚本负责限制请求形状、账户行、旧值及写后差异。它只生成本地请求，不接管连接器权限，也不是服务器端锁。

## 必须遵守的边界

- 从 manifest 取得 spreadsheet ID，从本轮元数据取得 sheet ID、标题和网格大小。按表头及账户、类型、标的确认目标行，不能沿用旧聊天中的行号。
- 写前读取目标工作表的**完整网格**，包含 `userEnteredValue,note,dataValidation,userEnteredFormat`。公式保存在 `userEnteredValue.formulaValue` 中；有效值不能代替用户输入值。空白尾部可由 Sheets 原生响应省略，但不能把局部读取伪装成全表。工作表超过脚本支持范围或工具不能取得完整字段时，表格待保存，其他独立保存位置分别处理。
- 每次计划只包含一个已确认账户。`scope.account_column` 指定账户列，`scope.account_value` 是该账户的原始 `stringValue`。每个目标行须匹配，不允许改账户列、覆盖公式、写公式或隐式清空；明确需要这些操作时另行审查，不能放宽此通路。
- `changes` 逐格给出零基行列、旧的原始输入值和新的有类型输入值。无输入值的旧格用 JSON `null`；文字 `"null"` 是 `{"stringValue":"null"}`，不可互换。未知值不得改零或清空。
- 只能原样提交脚本输出的 `requests`。每个 `updateCells.range` 必须包含起止行列，矩形与 `rows` 完全一致，`fields` 只允许 `userEnteredValue`。不得手写开放范围、改用 `start`、追加其他请求或把字段扩大为 `*`。
- 提交前再读完整网格，用 `preflight` 校验当前快照与计划基线一致；任何账户或元数据变化均停止争用。`preflight` 与提交之间仍有竞争窗口，不声称原子性或并发安全。
- 提交后重新完整读取，用 `verify` 比较整表全部已记录字段和网格元数据。只有预期的目标输入值可变；无关账户、备注、批注、验证规则、格式或公式变化均判失败。不能只读自己的两行就报告其他账户未变。
- `already_present` 计划不调用写接口；重复消息还须核对确认链，不能另建成交或再扣现金。回执不明时先读回，用原计划核验，不盲重试。
- 发现越界或其他异常立即停止本会话后续写入，保存私有原始快照、计划和回执，分别说明表格与确认链状态。不得继续制造“成功”日志，也不盲目整表回滚；恢复须核对最新变化并保留现场。

## 原生读取封装

将实际工具请求及完整原生响应程序化保存到私有 `capture.json`，不能靠模型重抄表格。封装键为：

- `spreadsheet_id`、`sheet_id`：本轮已核对的真实目标。
- `read_range`：完整 `GridRange`，起点均为 0，终点等于目标页签的 `gridProperties.rowCount/columnCount`。
- `read_fields`：本次实际请求的字段，逗号分隔字符串或字段名列表，至少含上述四个字段。
- `response`：Sheets 原生 Spreadsheet 对象，含 `spreadsheetId`、目标 `sheets[].properties` 和对应 `data[].rowData[].values[]`。允许连接器无损解包后的对象，不允许只传展示文本或二维值数组。

脚本只接受目标页签的一个从零开始的数据块。读取凭据与字段完整性依赖调用方诚实保存实际请求；脚本不能认证工具外手工伪造的响应。多页签可单独读取目标页签；请求不能触碰其他页签。

## 本地流程

在已验证的固定发布目录执行。下面的文件都位于私有目录，不进入公开提交；输入文件名仅作示例。

```sh
python3 -B scripts/holdings_guard.py snapshot --input _private/guard/before-capture.json --out _private/guard/before.json
python3 -B scripts/holdings_guard.py prepare --before _private/guard/before.json --scope _private/guard/scope.json --changes _private/guard/changes.json --out _private/guard/plan.json
python3 -B scripts/holdings_guard.py check --before _private/guard/before.json --plan _private/guard/plan.json
python3 -B scripts/holdings_guard.py snapshot --input _private/guard/current-capture.json --out _private/guard/current.json
python3 -B scripts/holdings_guard.py preflight --before _private/guard/before.json --current _private/guard/current.json --plan _private/guard/plan.json
```

全部通过且 `status=ready` 后，由已授权连接器向计划中的同一 spreadsheet ID **原样一次批量提交** `requests`。不根据输出摘要重新构造请求。随后重新读取完整网格：

```sh
python3 -B scripts/holdings_guard.py snapshot --input _private/guard/after-capture.json --out _private/guard/after.json
python3 -B scripts/holdings_guard.py verify --before _private/guard/before.json --after _private/guard/after.json --plan _private/guard/plan.json
```

每次读取保存为新的文件，不能覆盖旧候选。脚本的本地成功不等于云端提交成功；必须同时具备真实接口回执和 `verify` 成功。最后按持仓同步规范，分别处理确认链与近期记录。

## 必测反例

只在本地内存或虚构快照测试：缺少范围终点、范围大于数据、跨账户、重复目标格、旧值变化、公式覆盖、非有限数、空值、字段扩大、额外请求、提交前其他账户变化、不完整读回及写后非目标清空。不得为测试反例向云端发送危险请求。

`range` 未被 `rows` 覆盖的指定字段会被清空，这是 [Google Sheets UpdateCellsRequest](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/request#UpdateCellsRequest) 的接口行为；因此仅要求“最小修改”而不校验实际请求范围不够。
