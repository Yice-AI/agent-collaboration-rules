# 确认记录规范

本规范用于项目已授权的既有账户／通道字段保存。持仓表另按 [持仓同步](持仓同步.md) 更新，近期摘要另按 [近期记录规范](近期记录规范.md) 保存。三个结果分别核验。

## 允许保存的事实

- 只保存用户明确确认“已经发生”或“当前成立”的事实，保留实际来源与观察日期。建议、意向、预测、助手推断和计划日期到达不是确认事实。
- 仅使用本 release 的 `scripts/confirmed_ledger.py` 中 `TARGETS` 允许的既有字段及相应类型。新增或删除账户、嵌套字段、凭据、完整身份号码和无法核对的旧值不进入该链；不得临时扩展白名单。
- 事实日期、旧值或关键含义不明时只问影响保存的关键问题；不能编造默认值。表格能表达的已确认部分仍按其独立规范处理。
- 每次接续重新读取 HEAD。历史基线和聊天记忆不代表最新状态；仅有经过验证且仍可核对的缓存时才考虑增量读取。

## 读取并重放

1. 从私有索引的 `agent_runtime.resources` 取得 `baseline`、`ledger_head`、`ledger_folder`、`ledger_pending_folder`，按对象中的资源 ID 读取；基线预期哈希取 `baseline.sha256`。读取基线原始字节，核对 SHA256；不要将格式化或重新序列化后的 JSON 当作原始文件。
2. 读取 HEAD 的完整原生文档、正文和当前 revisionId；核对纯 JSON 正文结构、schema、基线、事件列表和末端。对本规范要求的单 JSON 段落，不混入标题、代码围栏或其他原生控件。
3. 完整分页列举正式目录，逐页原样传递分页令牌直到结束。目录应恰为 HEAD 与清单中的已提交事件；核对每份文件和目录的所有者、权限及父目录。未知清单外文件也必须报告，不能忽略或自动移走。
4. 按清单读取全部事件原文，验证 UTF-8 SHA256、事件 ID、父链、基线哈希、允许字段、类型、旧值及来源。使用 `cloud_ledger.materialize_manifest` 或等价完整校验；本地目录核验必须提供 HEAD 文档 ID，不能把 HEAD 当作孤立事件。
5. 从固定基线按提交顺序重放，只覆盖明确字段。缺文件、哈希不符、权限不明、目录不完整或链回退时，不能称“最新状态已核验”。重放结果可作当前分析或私有派生文件，不覆盖固定基线。

完整链核验只证明指定数据在本次读取中一致；不能据此认定所有平台、并发、恢复或后台任务均可靠。

## 条件提交

1. 完成上述校验后，用新 UUID 构造 `schema_version=1` 事件。`parent` 为已核验 HEAD 末端；`baseline_sha256` 与固定基线一致；`observed_at` 为真实事实日期；`recorded_at` 取实际时钟且含时区。`source.kind=user_confirmed`，`changes` 精确记录既有对象、字段、旧值和新值。取得不到真实会话／消息 ID 时按事件 schema 留 `null`，不编造标识。
2. 通过已授权工具在正式私有目录创建独立事件文档，保存单行 JSON。若工具先放在其他位置，先核对实际父目录，再移至已核验的正式目录。重新读取正文和权限，核对 UTF-8 哈希、事件内容和父目录；失败则不提交 HEAD。
3. 在已读 HEAD 清单末尾添加 `{event_id, document_id, sha256}` 并更新 `head`。以同次读取的 `requiredRevisionId` 条件提交完整正文替换。文本匹配兼容模式必须恰好替换一次；不能无条件覆盖，也不能用 `targetRevisionId` 自动合并。
4. 重新读取 HEAD、事件正文、文件权限，并再次完整列举目录。只有同一事件 ID、文档 ID、SHA256 全部一致、重放通过、目录无清单外项时，才称该链已保存，并给出事件 ID 和当前版本。

校验脚本只生成或校验数据，不代替云端授权、真实提交和读回。在固定 release 检出目录或已校验的备用目录根执行；候选输出限定在该目录的 `_private/` 内，并排除公开提交与 bundle。当前工具不具备所需条件写入能力时，保留待保存摘要，不降低要求。

## 重复、冲突和更正

- 写前先按原来源与内容排重；相同事实已经存在且核验一致时不再追加。
- 响应丢失或超时时，保留原事件 ID，先读回 HEAD、事件与权限；同一记录确已提交才补发成功回执。结果未明时标“写入结果待核验”，不得生成新 ID 盲重试。
- 修订冲突后重新读取最新状态，核对原事件和旧值。不能自行改父记录后原样重试，也不能覆盖其他写入者。相同 ID 对应不同内容时停止排查。
- 只有明确收到条件提交拒绝，或尚未尝试提交 HEAD，且确认本次创建的事件未列入最新 HEAD，才可核对其文档 ID、正文哈希、权限后移到 `ledger_pending_folder`。移后读回父目录和权限，重新完整列举正式目录。
- 写入结果不明时不得移动事件；未知来源的清单外文件也不得自动隔离。不能用移动或删除掩盖 HEAD 回退或未识别提交。
- 更正用新事件保留原来源和更正理由，不删除或改写旧事件。基线、既有事件、schema 或权限的修复另需明确授权与原样备份。

确认链失败不回滚表格或日志已经核验的结果；其余独立满足条件的保存继续进行。回复分别说明成功、无需变更、待保存或结果待核验，并交付尚未完成部分的 [待保存摘要](../templates/待保存摘要.md)。
