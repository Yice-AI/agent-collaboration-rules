# 原生快照传递

本协议解决原生 Sheets 响应到执行环境的传递，沿用[写入范围保护](写入范围保护.md)的封装和同版 `holdings_guard.py`，不改变字段、范围或写入权限。每个 App 必须在本轮独立验证整条通路；工具存在、文件生成或其他 App 通过均不算本 App 通过。

## 先发现能力

1. 发现当前会话实际可用的程序化工具调用、文件工具、代码执行及下载能力，读取真实 schema；不得猜造 API、输出参数或路径。
2. 程序化调用原生读取并持有返回对象。`exec` 隔离环境没有文件系统不等于没有通路：优先将动态生成的字符串作为实参传给其实际可调用的文件或执行工具。
3. 若没有直接出口，再使用下述私有 Google Doc 中转。全程由当前 App 自己调用，不要求用户上传或由另一个 App 代制附件；若最后无法打开真实文件，仍判传递失败。

## 保留原生证据

- 从 manifest 的资源映射定位表格；本轮读取页签标识、标题及完整网格尺寸，不沿用聊天记忆中的范围。
- 实际请求覆盖目标页签完整网格，包含 `userEnteredValue,note,dataValidation,userEnteredFormat`；保留公式、类型、空值、格式、验证及范围元数据，不用有效值替代输入值。
- 按既有规范程序化封装实际请求和完整原生响应；可无损解包连接器外层，不得只取展示文本、二维值数组或模型重抄内容。原生省略的空白尾部仍由既有校验器处理。
- 源对象、实际请求、完整正文和私有标识只留私有执行环境或专用私有文档，不打印到聊天、公开日志、报错、仓库或发布产物；回执只输出状态与必要摘要。
- 禁止以 Sheet 的 XLSX、CSV 或其他导出代替原生响应，再重建上述字段。

## 私有文档中转

1. 核对 `holdings_sheet.parent_folder_id` 指向的根目录及表格权限，在该根下新建本次专用 capture 子目录。目录、文档与源表须为同一 owner 且未共享；权限不可核实时停止，不通过共享、链接公开或扩大授权排障。
2. 创建新的空白单页签 Google Doc。按连接器真实 schema 放入 capture 子目录；若 OAuth 不支持创建时指定父目录，先建空文档，再用 metadata 更新迁移父目录，核对位置与权限后才写正文。不得向业务文档、确认链目录或近期记录目录投放中转文件。
3. 在程序中序列化原生封装，再转成纯 ASCII JSON；禁止手工重录、插入说明文字、Markdown 围栏或省略号：

```js
const source = JSON.stringify(capture);
const ascii = source.replace(/[\u007f-\uffff]/g,
  ch => "\\u" + ch.charCodeAt(0).toString(16).padStart(4, "0"));
if (JSON.stringify(JSON.parse(ascii)) !== source) throw Error("编码回环失败");
```

4. ASCII 编码保留中文、emoji 的代理对及私用区字符；Docs 会剥离部分控制字符和私用区字符，不能直接插入未经处理的任意 Unicode JSON。保留源字符串的 UTF-16 长度、UTF-8 字节长度，以及 ASCII 载荷的字节长度和可靠 SHA-256；哈希能力须有独立验证依据，不以模型口算代替。
5. 原生读取空文档及修订号，以 `requiredRevisionId` 条件写入程序变量中的 ASCII 正文。发生冲突、结果不明或写入失败时先核对现场，不盲重试，不覆盖旧捕获。
6. 原生读取该文档，程序化检查单页签结构并按顺序拼接文本节点，与写入变量严格等值比较。只允许依据已核实文档结构处理那个末尾 LF；禁止 `.trim()`、任意删换行或忽略不匹配。再解析 JSON，严格核对字段、类型、数组顺序、缺失值及元数据。
7. 用该 Doc 的 `export_file` 导出 `text/plain`，保留真实返回的文件引用；Google Docs 支持此格式。`files.export` 上限为 10 MB，超限即失败，不截断、缩字段或缩范围。若连接器明确支持，可实测流式 `fetch` 原生导出；仍受 Docs、运行时和工具各自限制。
8. 在当前 App 的执行环境实际打开文件。`file_uri`、`workspace_path`、附件引用和本地路径因平台而异，只使用本次返回且已验证可读的定位方式；不把另一个 App 的路径当作可用路径。
9. 先保存导出原始字节并记录长度、摘要，再核对其与 ASCII 载荷的关系。只允许处理本轮已证实的一个开头 UTF-8 BOM，以及已证实的 Docs 结构性末尾 LF；不移除其他位置或重复出现的字符，禁止 `trim` 或 Unicode `normalize`。处理后的载荷长度和 SHA-256 必须等于写入前记录，JSON 结构也须严格等值；仅“能解析”不足以通过。
10. 将经验证的载荷保存为私有 capture 文件，调用既有 `snapshot --input ... --out ...`。保留源、载荷、文档修订、导出字节及校验回执的私有关联证据；不把中转文档当作正式事实记录。

## 每阶段重新读取

- 写前基线、提交前 `preflight`、写后 `verify` 各自重新读取完整网格和元数据，并分别完成上述传递与 `snapshot`；每次使用新文档或新文件，不能复用旧捕获冒充新读。
- 继续执行既有 `prepare`、`check`、`preflight` 和 `verify`，只原样提交生成的逐格有界请求；传递成功本身不批准任何表格写入。
- 任一字段、权限、编码、摘要、文件读取或快照校验失败，停止该表后续写入并保留私有现场。分别说明失败阶段与其他独立保存结果，不用成功日志掩盖缺口，不盲目整表回滚。
- 捕获与提交间仍可能发生并发变化，文档条件写不提供 Sheets 原子性；按既有规则处理冲突和结果不明。
- 只报告本轮实际通过的 App、阶段与路径。云端文档中转、直接文件传递、后台执行和并发安全分别验收，不提前宣称全部平台可用。
