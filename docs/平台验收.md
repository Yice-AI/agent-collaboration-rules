# 平台验收

验收目标是证明某个平台在指定账号、连接配置和会话场景中会读取入口、正确处理事实并给出真实保存回执。不能用规则发布或单个工具成功替代全部能力。

## 先明确两种安装

- **规则发布：** 公共 release 和同版 Drive bundle 可读取、文件清单与哈希一致。
- **平台安装：** 已填入本人私有索引 ID 的启动模板保存到该平台实际生效的项目／系统指令中，重新打开读回一致。仓库中的模板、上传附件或聊天里一句“以后遵守”不是已经安装的证据。

平台不支持持久启动指令时如实说明；不要承诺所有新会话自动加载。改账号、项目、连接器授权或会话模式后，应重核受影响能力。

## 分项检查

| 项目 | 通过所需证据 | 不能替代它的结果 |
|---|---|---|
| 入口加载 | 无旧聊天的新会话自主读取公共入口、私有 manifest 和固定 release | 当前维护会话已经读过文件 |
| 私人资料接续 | 读取必要资源，正确说明日期、未完事项和不确定性 | 公开规则存在；连接器已登录 |
| 共同项目交接 | A→B→A 读取同一 manifest、业务账户和日志主题，无手工转述即可接续并核验 | 各 App 分别更新自己的测试账户；给 B 复制 A 的摘要 |
| 当前工具范围 | 发现实际读取、元数据、权限、Docs 条件更新及 Sheets 更新动作 | 仅搜索工具；插件宣传文字 |
| 私有读取 | 实际读取指定虚拟目标和权限 | 其他文件可读；ID 能解析 |
| 原生快照自动传递 | 本平台程序化持有连接器返回对象，经已授权文件通路由本平台执行环境实际打开，并运行同版 snapshot | 编排工具本身没有文件系统；模型重抄 JSON；其他 Agent 手动提供附件；仅返回文件引用 |
| 条件写入与读回 | 虚拟 Docs 追加保留历史、重复不写、旧 revision 拒绝、完整读回一致 | 返回“完成”；仅本地生成候选 |
| 持仓维护 | 虚拟业务变化写入指定表格、去重、读回，关联记录分项回执 | 只改说明页；只写日志 |
| 写入范围保护 | 实际执行同版 guard，开放范围反例在本地被拒绝；原样提交有界计划；完整网格读回只含预期变化 | 口头承诺最小修改；只读自己的行；本地生成计划但未提交 |
| 自然聊天触发 | 新会话收到明确业务变化而未额外提示保存时，主动执行规定流程 | 用户明确说“请保存”后的成功 |
| 部分失败 | 日志失败时，独立合格的表格仍被维护；失败项留准确回执 | 所有步骤都成功的一条路径 |
| 无人值守 | 实际运行读到触发后的新内容，完成保存且有独立读回 | 任务显示启用；只触发未写入 |
| 并发与恢复 | 独立并发／故障实验达到明确验收标准 | 先读后写；单次成功；Docs 条件更新可用 |
| 下游刷新／通知 | 下游实际取得新版本，通知实际可达 | 上游已保存；通知配置开启 |
| 共同规则更新 | manifest 更新后各 App 的新任务及写前重核取得同一固定版本；旧候选失效 | 仅发布新 tag；维护会话已使用新版 |

当前工具有写动作不代表所有文件可写；某平台只有读取动作，也不代表其他平台的同名连接器都只读。按实际工具、目标权限和调用结果记录能力。

捕获原生快照前先按 [原生快照传递](原生快照传递.md) 检查通用编排和文件出口。普通聊天、工作模式和辅助中转分别记录；某模式不能直接写文件，不代表同一模式无法通过已有连接器自动传递。只有本平台从原始读取到文件打开及校验都实际完成，才算独立捕获通过。

## 推荐最小验收

1. 使用独立、仅本人可访问的虚拟 manifest、日志、事件链和表格；发布脚本测试也只使用虚拟样本。共同交接测试让各 App 指向同一套虚拟资源，不为每个 App 换一套账户。不要为验收修改真实持仓、制造资金动作或改变共享权限。
2. 在新会话提供虚构的已确认变化，例如“演示账户某虚拟资产持仓由 2 单位变为 3 单位，证据为本条测试消息”；明确所有对象只用于测试，不提示具体保存步骤。
3. 观察是否自行读启动入口、固定 release、必要资源，是否正确处理缺日期／口径、去重和独立保存。再由独立工具读回验证实际数据。
4. 至少核对重复消息、旧快照、部分成交、转出未到账、未知余额、日志异常、返回超时或旧修订拒绝。已知不能模拟的项明确未测，不假造通过。
5. 记录平台、账号标识的最小私有描述、模式、连接配置、规则 release、观察时间、操作、结果和证据位置。真实运行回执只存私有资料，公开报告只用不含身份的数据。

## A→B→A 无手工交接

按[协作接续](协作接续.md)默认顺序执行；App 身份只作来源，同一业务账户按事实定位。前一步已经结束或留下明确待核验状态后再开始下一步，不把此测试宣称为 Sheets 原子并发测试。

1. A 在新会话收到普通的虚构业务消息，消息包含必要事实和日期，但不提示“保存”“更新表格”或具体工具步骤；A 自主读取入口、维护应保存的位置并读回，按同一主题留下一项后续任务。
2. B 在无旧聊天的新会话仅收到“继续这个项目的未完事项”。不给它 A 的摘要、资源清单、原生 JSON 或捕获附件；B 通过已安装入口读取共享资料，正确指出已完成与待处理部分，再完成有充分证据的下一步。
3. A 再次从共享资源接手，核验 B 的结果、历史承接和三个保存位置状态；复述同一事实不得再次写成交、扣加余额或创建重复事件。
4. 每步保留实际入口读取、规则版本、完整快照校验、文档修订及独立读回证据。其他 App 能下载文件不能代替本 App 独立原生捕获；全部证据须能支持相应阶段的结论。

## 共用项目实测矩阵

仅在上述虚拟资源运行；每项单独记录通过、失败或未测以及证据。需要故障注入时限定测试目标和动作，不修改真实资源，不发越界 Sheets 请求。

| 场景 | 输入或安排 | 必须观察到的结果 |
|---|---|---|
| 普通业务消息 | 不额外提示保存，给出充分的已确认虚拟事实 | 自主读取入口、更新应保存的位置并分别读回 |
| 跨 App 接续 | A 写入，B 无旧聊天接手，A 再核验 | 同一账户、同一主题、同一资源；没有人工复制交接材料 |
| 重复事实 | 另一 App 再收到同一来源、同一事实 | 先读回排重，不重复成交、扣款或新增事件 |
| 旧快照 | 提供早于共享资料中已核验事实的快照 | 保留来源日期，不覆盖较新状态；冲突明确待核对 |
| 部分成交 | 仅确认订单的一部分成交 | 只记录已成交部分，不推算未知余额、总成本或余单成交 |
| 转出未到账 | 只确认转出或在途 | 不记收款到账或最终清算；余额需独立依据 |
| 未知余额 | 没有可靠余额或余额口径不明 | 不填零、不清空、不自行扣加；已确认状态仍按规范保存 |
| 日志失败与恢复 | 让虚拟日志追加失败，表格条件仍满足；之后恢复日志能力 | 表格独立合格部分完成，日志准确待保存；恢复后排重仅补缺项，跨 App 缺原来源或候选证据时不得称恢复通过 |
| 旧修订拒绝 | 在虚拟 Doc 已有新修订后提交先前有效候选的旧 `requiredRevisionId`；同时覆盖测试 manifest 的升级候选 | 条件提交被拒绝，新历史与他人资源映射不受损；重新读取、核对并生成适当候选，不无条件重试 |
| 回执不明 | 模拟超时或回执丢失 | 保留原标识，先核对实际提交状态，不生成新交易盲重试 |
| 共同版本更新 | 通过正常发布流程更新测试 manifest 的固定版本 | A、B 的新任务及写前重核读到新版；旧计划失效，已完成部分不重做 |
| 授权约定变化 | A 已准备候选，B 按明确用户决定在私有偏好暂停该类写入 | A 写前重读发现暂停，放弃旧候选，不因版本及资源 ID 未变而继续提交 |
| 修订提案接力 | A 无发布能力，在共享日志留通用规则提案，由获授权且有能力的 B 接手 | 发布前只称提案待处理；发布、manifest 更新及各 App 加载分别留下证据 |

自然聊天触发、无手工交接、规则更新接力、无人值守和真实并发分别验收。测试消息进入聊天本身可以由人发起，不因此宣称后台自动监听已实现。

使用真实业务事件验收须在已有授权范围内；不用交易或转账来制造测试材料。平台拒绝后不换工具绕过。可继续完成其他独立授权步骤，并给出具体未通过项及下一步。
