# 入口与版本

平台必须有一条实际生效的启动指令，提供用户私有资料索引的 ID。索引中的 `agent_runtime` 是运行 manifest，指向公共规则及私人资源。仅上传文件、连接 GitHub、打开项目页面或保存一份指令维护稿，不保证新会话会读取它们。

## 接手顺序

每轮新任务都重新读取索引中的规则版本；业务写入前再次核对该版本、资源映射与当前偏好中的适用授权和暂停项。只有版本指纹一致才可复用已经验证的规则内容。版本、目标或允许范围变化时停止使用旧候选，加载当前规则并按最新业务状态重新准备；不要求用户逐个通知其他 App。

1. 从平台启动指令给定的 ID 读取私有原生 JSON 索引；核对目标、完整正文、所有者和共享权限，解析 `agent_runtime`，核对 `schema_version=1`、`release` 和 `resources`。不要通过公开搜索泄露私有 ID 或正文。
2. 读取 `release.repository_url` 中 `release.commit` 指定的完整提交，核对 `release.version` 及发布校验信息。具体规则和脚本必须来自同一精确版本；默认分支仅作导航，不能替代固定提交。若版本不存在、校验不符或文件混用，停止依赖这些规则的写入并报告缺口。
3. 读取固定版本的 `SKILL.md`（旧版本没有该文件时用 README），再读取 `resources.preferences` 和 `resources.project_context`，了解当前授权范围、个人偏好、背景和已有工作。历史业务描述仍须按其来源与日期使用。
4. 实际读取 `resources.work_log`，按主题找最后状态。完整结构异常时停止日志追加，保留已读内容的校验缺口；不要因此漏掉可独立完成的持仓同步。
5. 当前任务涉及正式账户或通道事实时，按 [确认记录规范](确认记录规范.md) 读取固定基线、HEAD 和完整事件链。涉及持仓、成交、现金或转账时，同时读取 [持仓同步](持仓同步.md) 规定的表格范围。
6. 只补充当前任务需要的原始证据。已有明确需求时直接处理，不为填满资料表重复询问。

## 私有资源映射

资源的真实文件 ID、URL、基线哈希和其他项目特定值仅放在私有索引或其授权指向的私有配置中。每个资源是对象，包含 `type` 和 `file_id`；表格使用 `spreadsheet_id`，需要原文字节校验的资源同时带 `sha256`。`resources.work_log.parent_folder_id` 必须登记近期记录的预期私有父目录；不能用现场读到的任意目录反过来充当预期值。实际所有者、权限和父目录必须从连接器读取并核对。具体 manifest 格式以该 release 的 schema 和校验器为准，不由 Agent 临时创造字段。

| 资源键 | 内容与职责 |
|---|---|
| `resources.baseline` | 事件链绑定的固定基线原始文件；按预期 SHA256 验证 |
| `resources.ledger_head` | 正式事件清单和链头的原生 JSON 文档 |
| `resources.ledger_folder` | HEAD 与已提交事件的正式私有目录 |
| `resources.ledger_pending_folder` | 经规范确认可隔离的未提交文档目录 |
| `resources.work_log` | 追加式近期工作记录，含预期私有目录 `parent_folder_id`；不是余额或账户事实的替代台账 |
| `resources.holdings_sheet` | 已有持仓表；保留同一文件，不新建同名副本 |
| `resources.preferences` | 当前个人偏好、授权和维护约定 |
| `resources.project_context` | 私人项目背景、角色、已知问题及其他资料导航 |

记录中旧仓库路径或旧配置名称只是历史来源；迁移前配置只作历史缓存，不再维护。资源映射须提供直接可用的 Drive 入口；不能要求日常 Agent 再访问私有 GitHub 才能取得基线、个人偏好或业务证据。

已取得可信的固定 release 后，可在该目录根使用本地校验入口：

```sh
python3 -B scripts/runtime_manifest.py validate --input _private/catalog.json
```

输入可为含 `agent_runtime` 的完整私有索引，或独立运行 manifest 对象。此命令只校验本地结构，不联网读取资源、不验证云端权限、不保存或部署任何配置；成功不代表所有资源可用。原始输入只留私有工作目录。备用包还未通过下述外层字节哈希时，不得先运行包内这个脚本来建立信任。

## 版本与备用

- `release` 包含 `repository_url`、`commit`、`version`、`bundle_sha256`、`fallback_document_id`；这些实际值来自本轮读取的私有索引，不写入公共模板。每轮报告本次实际使用的版本与完整 commit。文件修改时间、标题或助手说“最新版”不能替代精确版本和内容核验。
- 私有 manifest 固定版本不等于持续追随最新发布。正常执行不自行切换版本，也不因看到新 tag 就更新项目。
- 公共来源临时不可读时，读取 `release.fallback_document_id` 的原生文档正文，作为同版 bundle JSON。**先用独立于待验证包的可信哈希能力**核对完整原始字节与私有 manifest 的 `release.bundle_sha256`。可使用平台既有的原始字节哈希工具或已验证的校验器；通过前不得执行、导入、安装包内脚本，不能由待验证内容为自身背书。
- 外层原始字节哈希通过后，才能使用包内 `scripts/build_bundle.py verify` 检查版本、结构、清单及逐文件哈希；也可全程使用等价可信校验。bundle 格式为 `schema_version`、`version`、`files`，文件项为 `path`、`content`、`sha256`；发布元数据 `release.json` 不纳入 bundle，避免自引用。`version` 还必须与私有 manifest 一致；不能只凭包内自报信息认定同版。
- bundle 原文是单行 UTF-8 JSON，无末尾 LF。从原生 Doc 提取时，先核验单段纯文本结构，只允许去除已确认属于文档结构的那个末尾 LF；不能任意 `strip`、重排 JSON 或忽略额外内容后再计算哈希。缺少可信原始字节哈希能力时，保留备用包未核验状态，不进入依赖该包规则或脚本的写入。
- Drive 备用是发布产物，不是第二个编辑源。修正规则回到公共源，经测试发布，再刷新备用和私有 manifest。
- 缺 manifest 或缺关键权限时，继续不依赖私人事实的工作；当前账户、余额或保存状态明确标未核验。不能为了完成接入而公开私人文件或要求用户复述全套背景。
- 同一平台不同账号、会话模式或连接配置可能有不同能力；接入证据仅适用于其实际验收范围。
